# Proposal: Generative Research-Front Discovery

**Status**: Draft
**Date**: 2026-03-30
**Priority**: P3 (backlog -- after current pipeline validation and cross-domain work)

---

## Problem Statement

FrontPulse currently operates in a **confirmatory** mode: a human selects a
domain (PSC, CRISPR), the pipeline ingests that domain's literature, and the
multi-signal detector predicts which lineages within that domain will experience
onset. The model is trained and evaluated on historical inflection points derived
from the same data. This is useful but limited in two ways:

1. **Domain selection is manual.** The system only monitors what someone thinks
   to look for. Emerging research fronts that span unexpected disciplinary
   boundaries or arise in areas no one is watching go undetected.

2. **Labels are self-referential.** Onset labels are derived from growth-curve
   inflection points in the data itself. The model predicts a statistical pattern
   using features computed from that same data. This circularity limits the
   epistemic value of the predictions.

## Proposed Capability

Invert the pipeline: instead of monitoring predefined domains, apply the trained
MSD to a **broad** OpenAlex domain (thousands of lineages) and surface the ones
predicted to undergo onset that **no human has yet flagged as emerging**. The
output is a ranked list of research-front candidates -- genuinely novel
discoveries generated by the system rather than confirmations of known trends.

### Concrete Example

1. Define a broad domain config (e.g., "Biotechnology," "Materials Science," or
   "Environmental Engineering" -- a topic with 200K-500K works and thousands of
   Leiden lineages).
2. Ingest from OpenAlex, build citation graphs, run Leiden clustering.
3. Compute the full feature matrix (core + context + convergence).
4. Apply the CRISPR-trained MSD model **without retraining** (transfer learning).
5. Rank all lineages by predicted onset probability.
6. Filter to lineages NOT already labeled as "emerging" in any existing taxonomy.
7. The top-N surviving lineages are the **discoveries**.

### Retrospective Validation Design

To validate without waiting for real-time quarters:

- Ingest the broad domain using data available **as of 2020** (use date filters
  or temporal cutoff).
- Apply the MSD to 2020-era features, generating predictions.
- Then compare against what actually happened in 2021-2026: which predicted
  lineages exhibited >3x growth, received major grants, spawned clinical trials,
  or were recognized in review articles?
- Compute hit rate vs. base rate for quantitative evidence.

This produces a finding like: *"We applied the model to domain X using 2020 data
and identified 47 lineages predicted to undergo onset. Of these, 23 (49%)
subsequently exhibited >3x growth by 2024, compared to a base rate of 8% across
all lineages."*

## Why This Over Other Improvements

| Alternative | What it does | Why it's less impactful |
|-------------|-------------|------------------------|
| SPECTER2 upgrade | Better embeddings | Incremental quality gain |
| More HPO tuning | Better params | Diminishing returns |
| Holdout evaluation | Stronger validation | Still confirmatory |
| Cross-domain transfer | PSC model on CRISPR | Tests generalization but still predefined domains |
| **Generative discovery** | **Surfaces unknown fronts** | **Qualitatively new capability** |

## Alignment with Dissertation

The dissertation examines "AI transformation of scientific research through
institutional/governance dimensions and computational methods for tracking
knowledge dynamics." An AI system that discovers emerging research fronts
before human experts notice them is the most direct demonstration of that
transformation. It moves beyond tracking dynamics to producing actionable
foresight -- the kind of output that science policy organizations
(NSF, OSTP, national academies) would consume.

## Technical Feasibility

The pipeline infrastructure already supports this:

- **Domain isolation** (FP-5uo): New domains are a config change, not a code
  change. Add a YAML datasource config and a DOMAIN_REGISTRY entry.
- **Multi-domain pipeline** (validated for PSC and CRISPR): The same code
  handles any domain.
- **Convergence features** (FP-w2w): Work across any set of lineages.
- **MSD transfer**: CatBoost models generalize across domains if the feature
  space is consistent (same column names, same computation logic).
- **Quarterly slicing**: The retrospective validation design reuses existing
  slicing infrastructure with a date cutoff.

### Key Technical Risks

1. **Scale**: A broad domain may have 5,000-50,000 lineages vs. PSC's 5,179.
   The pipeline handles PSC's scale; 10x may require chunking or sampling.
2. **Transfer gap**: The CRISPR-trained model may not transfer cleanly to a
   domain with very different citation dynamics (e.g., humanities). Initial
   targets should be adjacent STEM fields.
3. **Label quality**: Retrospective validation requires defining "successful
   onset" from external signals (growth, citations, grants). This definition
   is a judgment call that affects the results.
4. **Compute**: Full pipeline for a 500K-work domain takes ~8-12 hours (based
   on PSC and CRISPR run times). Manageable on current hardware but not fast.

## Success Criteria

1. The system produces a ranked list of predicted emerging fronts from a domain
   it was not trained on.
2. Retrospective validation shows the predicted fronts have a hit rate
   significantly above the base rate (>2x).
3. At least 5 predicted fronts correspond to research areas that were
   subsequently recognized as emerging in review literature or funding
   announcements.
4. The results are framed in a publication-quality analysis suitable for
   inclusion in the dissertation or a standalone journal article.

## Open Questions

- Which broad domain to target first? Candidates: Nanotechnology, Biomedical
  Engineering, Renewable Energy, Computational Biology. Should overlap enough
  with CRISPR/PSC for transfer learning but be distinct enough to demonstrate
  generalization.
- What external validation signals to use? Options: citation growth (simple),
  patent filings (requires PatentsView data), grant awards (requires NSF/NIH
  API), review article mentions.
- Should the model be applied as-is (pure transfer) or fine-tuned on a small
  set of labeled examples from the new domain (few-shot adaptation)?
- How to handle lineages that span the boundary between the training domain
  and the target domain? These should be excluded from the "discovery" list
  to avoid circularity.
